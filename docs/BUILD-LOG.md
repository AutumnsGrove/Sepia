## 2026-10-31, S00.1-S00.4, the walking skeleton

**Built.** `go.mod` (module `github.com/AutumnsGrove/sepia`, `go 1.26`), the Makefile (`check`, `test`,
`e2e`, `gen`, `web`, `web-check`, `guard`, `nocgo`, `fuzz-smoke`), `.golangci.yml`, `.editorconfig`,
`STACK.md`, `SECURITY.md`, `CODEOWNERS`, the architecture test, the server skeleton, the embedded frontend,
the world harness and `cmd/sepia-dev`.

**What is true now.** `GET /healthz` answers exactly `{"status":"ok","version":"dev"}`; the Host check refuses
anything off the allow-list on every route; a state-changing request or a socket upgrade without our own
`Origin` is refused; unknown `/api` paths and wrong methods answer the JSON envelope; a hostile header over
16 KiB is refused; the frontend is embedded and served with brotli or gzip chosen from what the client
accepts; SIGTERM drains and exits 0. The architecture test fails the build on any import that breaks
`BUILD.md` 4, proved by adding `domain -> store` and watching it go red.

**Learned, for the next agent.**

- **SvelteKit 3 moved configuration out of `svelte.config.js`** into the `sveltekit()` plugin in
  `vite.config.ts`, and route options now travel as `export const config`. The old file is a hard build error
  (`config_file_unsupported`). `tsconfig.json` must extend `"$app/tsconfig"`.
- **A stray `~/node_modules/cookie` on this machine shadowed pnpm's copy** during the post-build route
  analysis, which resolves from `.svelte-kit/output`, not from Kit's own directory. `cookie` is therefore an
  explicit dev dependency: it is a genuine phantom dependency of the analysed output, not a workaround.
- **`svelte-check` was green while the page rendered unstyled**, because deleting `+layout.ts` took the
  `app.css` import with it. Rendered and looked, as the mockup rule says.
- **The guard script caught two of its own rules** on first run: a test calling `http.Get` and one using
  `http.DefaultClient`. Both were rewritten against a context, and the rules stay strict.
- The `drift` CI job waits for S02, because there is no `api/` contract to regenerate yet.

**The first CI run found three things, all fixed in the same slice.** `web` could not start pnpm, because the
app never said which version it uses (it does now, and the action is told where `web/package.json` is). `nocgo`
listed `runtime/cgo` because it ran `go list` with cgo on, which is the opposite of what it claims to check.
`internal/config` was at 65% coverage, below the floor the job asserts, so the derived origin list and the
startup consistency check got tests.

**A false positive was removed from history rather than allowlisted.** gitleaks flagged the RFC 6455 handshake
key in a test as a generic API key. The commit was amended to build the nonce from a low-entropy string, so no
allowlist has to hide a test file from the scanner forever. Nothing but the branch tip had been published. The
guard script also stopped running its own `gitleaks`: one scanner, in CI and in `make gitleaks`, so the two can
never disagree about the rules or the version.

**CI is green on `main`** for all seven jobs: `go`, `nocgo`, `coverage`, `web`, `e2e`, `guard`, `codeql`
(`deps` is pull-request only until S13). Getting there took five runs, and every failure was a real one: the
pnpm version, the cgo check running with cgo on, config coverage, missing Node type definitions, and a Prettier
format. The screenshot baseline needed a different fix: Chromium and WebKit on Linux rasterise glyphs 2% away
from macOS, so each platform now has its own baseline and the Linux ones were generated by the `baselines`
workflow on the runner that compares against them.

**Live checks left for Autumn:** the repository settings in [`REPO-SETTINGS.md`](REPO-SETTINGS.md), which are
the only part of S00 that cannot live in the repository.

## 2026-10-31, S03, the domain core

**Built.** `internal/domain`: the rating parser (quarter-stars, snapping, Unicode digits), date resolution
against the phone's zone, the span locator with its normaliser and closest-passage search, format cues, title
matching, the merge, and the save guard with the entry and diff types. 95.6% coverage, two fuzz targets, and
six property tests over generated input.

**What is true now.** A quote the operator never wrote cannot become a body: it is dropped and logged, and
`ValidateForSave` refuses an extracted body whose spans are not in her messages. A one-word slip or a homoglyph
lands on her own wording; a short quote has to match exactly, because one edit turns "dune" into "done". A merge
never takes a web field without an accept tap, never loses a trusted field, and is idempotent.

**Learned, for the next agent.**

- **Fuzzing paid immediately, three times.** `findExact` could spin forever when a quote only appeared inside
  longer words; the normaliser appended one origin offset per *rune* while writing *bytes*, which shifted every
  later span; and the Unicode digit helper counted back to a block start, which returns 10 for the mathematical
  digits because their blocks abut. None of these would have been found by the example tests, and all three are
  now regression seeds under `testdata/fuzz/`.
- **A lookalike is not a failure to match.** The first instinct was to reject a Cyrillic "е" outright. The
  invariant is about what is *stored*, not what is matched: matching it and storing the source's own word is
  both safer and more useful for screenshot imports.
- **`Compose` needs a separator rule, and the invariant needs to survive it.** Joining two passages with a
  newline adds a character she did not write, so containment is proved per span and the newline is documented in
  `ENTRY_CARD.md` rather than quietly appearing in a saved body.
- **The thresholds are starting values.** The cutoff (0.72) and the minimum fuzzy length (12) are guesses with a
  test, not measurements. G4 replaces them with real odds.

## 2026-10-31, S02, the contract

**Built.** `api/events.schema.json`, `api/openapi.yaml`, `api/error-codes.json`, 34 golden examples in
`api/examples/`, `internal/contract` (the Go validator and the generated code registry), the TypeScript types
and validator under `web/src/lib/contract/`, `tools/gen`, `web/scripts/gen-contract.mjs`, `make gen`, and the
`drift` CI job.

**What is true now.** A frontend agent can build a screen from the generated types and an example without
reading server code; a backend agent can build a handler from the schema without reading the UI. The same
schema document validates in Go (santhosh-tekuri/jsonschema) and in TypeScript (ajv), so a fixture cannot pass
on one side and fail on the other. `make gen` is idempotent, and CI fails when it is not.

**Learned, for the next agent.**

- **A colon in an unquoted YAML scalar is a parse error**, which `openapi-typescript` found in a `summary`. The
  contract files are linted by being parsed, so a typo fails the generator rather than the frontend.
- **Two ajv entry points cannot share a `$id`.** The schema is compiled twice, once for server events and once for
  client messages, so the `$id` is dropped when the entry point is attached.
- **Generated files must be excluded from ESLint and Prettier**, or every run of `make gen` fights the formatter
  and the drift check never settles. They are still type-checked by `svelte-check`.
- **The Go event structs wait for S07.** Nothing calls them yet, and generated code that nothing calls is where
  drift hides. The drift job covers what is generated today.

## 2026-10-31, S04 in progress, the data layer's foundations

**Built so far.** `internal/store`: the schema with every table and index from PLAN.md 6, eight triggers, the
migration runner (append-only, positional, one transaction per file, refuses a newer file), the doctor (integrity,
trigger presence and permissions) and its active probe, the writer/reader split, and `sqlc` with 45 queries
generated into `internal/store/db`. `make gen` now regenerates the SQL code too, and `drift` covers it.

**What is true now.** No SQL the application, a test or a manual shell can run will delete a review, rewrite a
revision, edit a source snapshot, or drop an answer. A source may be accepted exactly once. A saved entry never
returns to a draft. A process killed mid-transaction leaves a database that still opens, passes the integrity
check, and has none of the half-written row. A database from a newer binary refuses to open.

**Still to do in S04.** The repository layer over the generated queries (works, entries, answers, revisions,
sessions, events, media, mirrors), the cursor-paginated library and drafts queries with `EXPLAIN QUERY PLAN`
tests, event-log compaction, and the restore path. The slice stays "in progress" until those land.

**Learned.**

- **`sqlc` and repeated named arguments disagree.** A named argument used three times in one query produced three
  `?` placeholders but one struct field, so the driver got fewer arguments than it wanted. The fix was a
  row-value cursor comparison with positional parameters, which also lets SQLite walk the index.
- **An empty table fires no trigger.** A probe that deletes from `entries` before any row exists passes whether or
  not the protection is there, so the doctor writes probe rows inside a transaction and rolls the whole thing back.
- **A failed migration must not stamp its version.** The schema change and `PRAGMA user_version` share one
  transaction, and a test asserts the version does not move when the SQL is broken.

## 2026-10-31, S04 done, the data layer

**Built.** The repository layer over the generated queries: works and sources (with the one allowed update),
entries (draft, confirm with its revision in the same transaction, soft delete, restore, the library with a
cursor, drafts, a work's timeline), answers, revisions, sessions, the event log (append with a sequence number,
replay since N, compaction of streamed chunks), tags, media and mirrors. Two migrations, eight triggers, the
doctor, and an `EXPLAIN QUERY PLAN` test for every list query.

**What is true now.** The database refuses what the rules forbid, with raw SQL, whatever the Go code above it
believes. The library pages by cursor and never repeats or skips a row. A confirm over a saved entry writes the
previous version first, in the same transaction; the first confirm of a draft writes nothing, because a draft is
not a version.

**Learned.**

- **A migration is not a place to change a query's shape by memory.** Adding the tiebreaker column to the list
  indexes removed a temporary B-tree from every page, which the `EXPLAIN` test now asserts, so the next person to
  touch an index finds out immediately if the sort comes back.
- **`RowsAffected` is what makes an accept honest.** The update's own WHERE clause is the guard, so a second
  accept changes nothing and reports nothing; the repository turns that zero into `ErrNotAcceptable` rather than
  letting a tap look successful.
- **A fixed identifier source in a test is a trap.** The first version of `openTest` returned one id forever, so
  every insert after the first collided on the primary key and the failures looked like repository bugs.

## 2026-11-01, S05, banks and decisions

**Built.** `internal/banks` (the strict loader for `config/questions/*.yaml`, the pure selection, two fuzz
targets and a polling store) and `internal/decisions` (the registry over `config/decisions/{wording,policy}.yaml`,
the policy engine, the pre-read and the fidelity call over nova's `decide` contract, and its own store).
`internal/world` gains the decisions fake, scripted per check with every fault.

**What is true now.** The shipped banks and registry load, and a bad one is refused with the file and key named
while the previous config keeps serving. A form shows the tabs in PLAN.md order, hints first and dashed, at most
three questions by weight, and never a question whose topic the message already covered. One batched call sends
13 checks with the message, the open question and the work title as separate sources; policy then applies the
thresholds, the option thresholds, the intent gates, the split-medium rule and the session override. A timeout,
an outage, a malformed answer or an answer that contradicts its own probabilities leaves the turn to run with a
notice. `adds_content` is logged as a bug and never shown as a warning.

**Learned, for the next agent.**

- **A YAML map has no order, so the quiet option had to become a key.** The draft's "the first option is quiet"
  would have been silently positional. `quiet: <option>` is validated against the options and is the one name
  policy may never give a threshold.
- **The split-medium rule must run before the threshold.** Dune's book 0.55 / film 0.40 is below the 0.70 bar, so
  a threshold-first engine would have asked nothing and guessed nothing. The ambiguity rule is the whole point
  of that read.
- **`only_when_intent` had to move from request time to policy time.** Intent is decided inside the same batched
  call, so gating before the call is impossible; the checks are always sent and policy ignores the ones that do
  not apply. Medium joined that list: a medium with no route is not a hint, it is noise.
- **The digest of a config file is not the file.** Polling by mtime and size is enough for a hand edit, and it
  behaves on a bind mount where inotify does not. A broken edit is stamped too, so the notice is raised once
  instead of on every tick.
- **A threshold above an option threshold is a load error, and it caught a test fixture.** The reload test tried
  0.90 on intent while its `log_review` option needed 0.80; the loader refused the edit and the test hung. The
  rule is right: the option bar must be the stricter of the two.
- **`yes` and `no` are plain strings in YAML 1.2.** `gopkg.in/yaml.v3` does not turn them into booleans, so the
  draft's quoting is harmless rather than load-bearing here; duplicate keys and unknown keys are both errors, and
  `KnownFields` only applies through a `Decoder`, never through `Unmarshal`.

**Not wired yet, by design.** `Store.Watch` is built and tested but nothing starts it: the server that would
surface a reload notice and serve a form arrives in S09. S09 wires both stores, `sepia-dev` loads them offline,
and S13 bind-mounts `config/`.

**Live checks left for Autumn:** none for this slice. The thresholds are the draft's and G4 replaces them.

## 2026-11-01, S05 follow-ups

**CI and the rules caught three things, all fixed in the slice.**

- **`make check` could not run two fuzz targets with the same name.** The `fuzz-smoke` loop took the first file
  that declared a target and `cd`'d into its directory, so `FuzzLoadFiles` in both `banks` and `decisions`
  broke it. The targets are now named for what they load, and the loop iterates every file, so a name may be

- **The architecture test caught `decisions` importing nova's `provider` package.** That is the type of the

  for that adapter explicitly, in `BUILD.md` 4 and in the allow table, rather than being loosened for all of

- **The coverage job needed floors for the two new packages.** `banks` sits at 85% and `decisions` at 88% now,
  and both are above them; they parse hand-edited YAML and turn it into routing, which is critical enough to
  hold to the same standard as `server` and `store`.

## 2026-11-01, S06, providers

**Built.** `internal/providers`: one package with the TMDB (film and TV) and Open Library (books) clients, the
normalisation into `domain.Source` and `domain.Work`, the in-memory answer cache, candidate ranking, cover
download and storage, and typed errors for every failure. `internal/world` gained real fixtures per route, a
429 with and without `Retry-After`, a 404, a stalled reply, and a recorded query string. `internal/config` reads
`SEPIA_TMDB_API_KEY` and `SEPIA_DATA_DIR`.

**What is true now.** A title returns ranked candidates and at most five; a fetch returns a verified source with
the provider's own document alongside it, and a stored cover under `data/covers/{provider}-{id}.{ext}` that is
refreshed after 180 days. A missing key is "off", not an error; a 404, a 5xx, a 429, a timeout, a stalled body,
a huge body, HTML instead of JSON and a control or bidi character in a title each end in one typed reason the
agent can turn into the lookup_failed card. Nothing in a provider request can hold an opinion: the query is
`medium`, `title`, `creator` and `year`, and a test asserts the wire carries only that plus the key.

**G3 is answered** and committed in [`handoffs/2026-11-01-G3-tmdb-terms.md`](handoffs/2026-11-01-G3-tmdb-terms.md).

**Learned, for the next agent.**

- **A provider id needs its kind.** TMDB movie 603 and TV 603 are different works, so the stored id is
  `movie:603`/`tv:603`. A bare number would merge two unrelated things.
- **The cover size check must run before the decode.** A 4,000-pixel limit enforced by decoding first is a
  decompression bomb with a polite message.
- **A file's modification time is the cheapest cache timestamp, but only if you set it.** The freshness test
  failed until the writer set mtime from the injected clock: the file had the machine's time and the rule had
  the test's. `os.Chtimes` makes one source of truth.
- **A bidi override is a display attack, not a curiosity.** U+202E in a title can reverse what a card shows
  while a model still reads the real words. Both loaders strip control, format and bidi characters and separate
  runs with a space.
- **Open Library names authors by reference.** A work lists author keys, so a fetch is up to four requests. Author
  and edition failures are skipped, and only a cancelled caller aborts: a thinner work beats no work.
- **`unparam` and `gosec` caught two real things**: a `coverURL` parameter nothing used, and a 0755 cover
  directory. Neither would have failed a test.
- **An `*http.Client` set only in `withDefaults` is a nil pointer when a caller builds a client directly.** The
  client constructors now apply the defaults themselves, which is also what makes them usable in a test.

**Not wired yet.** Nothing constructs the `Finder`: the agent that calls it arrives in S08. The attribution text
and logo are shipped as constants/assets here and placed in the UI by S11 and S12.

**Live checks left for the operator:** a real TMDB key, and real data for a book, a translated book, a film, a
miniseries and a remake, as the slice's Done-when says.

## 2026-11-01, S07 in progress, the session engine's spine

**Built.** Migration 0003 (a `draft_version` on sessions, `interactions`, `client_messages`, and two triggers that
refuse to reopen or delete a question), the queries and store transactions over it, and `internal/session`: the
lifecycle, `hello` with replay and a `full_state` fallback across a compacted gap, ask/answer/withdraw with the
first answer winning, the idempotency ledger, the per-turn delta compaction, and the waiting-reason rules.

**What is true now.** A question and the event that announces it are written in one transaction, so a restart
cannot lose one; an answered question cannot be reopened or deleted even by raw SQL; a stale draft version changes
nothing; two appends at once get distinct, gapless sequence numbers (`-race`); a client resuming into a compacted
gap is told to rebuild from the snapshot instead of replaying a hole.

**Blocked, and it is a schema finding worth reading.** `entries.rating_q` is `NOT NULL CHECK (rating_q BETWEEN 1
AND 20)`, so an **unrated draft cannot be stored**, and the Drafts list exists to show exactly that state
("Needs a rating" in `mockups/03-home-and-library.html`). Two tests are skipped until it is fixed, and they are
the tests that will prove the fix. The options are a table rebuild of `entries` to allow `0..20` (SQLite's
documented rebuild needs `PRAGMA foreign_keys=OFF` around the transaction, which the migration runner does not
offer yet) or a nullable rating column added beside the old one. Both are migration-runner or schema changes, not
engine code, so they are recorded here rather than forced in at the end of a long turn.

**Still to do in S07.** The draft operations (edit, accept fields, include left out, confirm, discard, stop) with
the version check; the confirm's single transaction (version, entry, revision, session link, state, events,
ledger); revisit and edit-existing; the session and message limits; and the wire shapes S09 will serve.


## 2026-11-01, S07, unrated drafts and the rebuild it needed

**The finding, fixed.** `entries.rating_q` was `NOT NULL CHECK (BETWEEN 1 AND 20)`, so a draft with no rating could
not be stored, though the Drafts list exists to say "Needs a rating". 0 now means "not rated yet" and every real
rating is still 1..20. SQLite cannot widen a CHECK in place, so migration 0004 rebuilds the table the documented
way: columns, three indexes and both triggers reproduced exactly, the copy in one transaction, and a commit only
after `PRAGMA foreign_key_check` and `PRAGMA integrity_check` come back clean.

**The runner learned one directive.** A migration may begin `-- pragma: foreign_keys=off`; the runner turns
enforcement off on a pinned connection, runs the file in one transaction with the checks above, and turns it back on
whatever happens, including a cancelled context. An unknown directive is a load error rather than a comment, because
a migration that silently did not get the mode it asked for is worse than one that will not run.

**Tests.** The marker parser, enforcement being on after a rebuild, a second rebuild over live rows keeping them and
their rules, a rebuild that leaves a dangling reference being rolled back with the version unmoved, and the save
guard still refusing to confirm an unrated draft. The two skipped session tests are live again, so the Drafts list
now has its happy, bad and sad routes.


## 2026-11-01, S07, the draft operations and the confirm

**Built.** `store.UpdateDraft` and `store.ConfirmDraft`: one transaction each, covering the version check, the
field write, the snapshot event and the client-message ledger. `session.EditDraft` validates a field patch by name
and range before anything is written; `session.Confirm` runs the domain's save guard first and then commits the
entry, its revision, the session link, the closed state, the snapshot and saved events and the ledger row together;
`session.Discard` closes without deleting; `session.AppendUserMessage` enforces the 8,000-character and 200-message
limits and refuses a replayed `client_msg_id` before storing anything.

**What is true now.** A stale edit is refused with a current-version code and changes nothing. Two devices
confirming produce one save, because the second finds the version stale or the session closed. A body that claims
to be extracted from her words but is not is refused by the guard before the transaction opens. Discarding keeps
the draft: nothing is deleted, ever.

**Still to do in S07.** `accept_unverified` and `include_left_out` (both are store calls the engine can wrap),
revisit/edit-existing as a first-class flow (the confirm already writes a revision when it replaces a saved entry),
the one-deep message queue and the question-round cap, and an engine test that a killed process resumes with the
draft, the open question and the log intact (the store's restart tests cover the pieces; the assembled route is
S09's).


## 2026-11-01, S07, accepting a web field

`Engine.AcceptFields` and `store.AcceptDraftSources` land the one tap that turns a proposed fact into a canonical
one (docs/BUILD.md invariant 7): the version moves, the source's trust moves from unverified to accepted, the
snapshot event and the ledger row are written, all in one transaction. The client names a field by what it saw,
`provider|id`; the store names the row by the same pair, so a client never has to know a database id. The
database's own trigger refuses a second accept, and that refusal is surfaced as `already_accepted` rather than a
tap that appears to work twice.


## 2026-11-01, S07, putting a left-out passage back

`Engine.IncludeLeftOut` adds one of her own passages back into an extracted body. The span is proved against her
messages with the domain's containment check before anything is written, the spans are stored in source order so
the body reads the way she wrote it however they were added, and the body is recomposed rather than appended to:
an extract is a set of her passages, not a string that grows. A typed body has nothing left out of it and says so;
a stale version changes nothing.


## 2026-11-01, S07 done, the session engine

**Built.** Revisit and revision (`OfferRevisit`, `StartRevision`, confirm with `revises`), the four-round cap
(`AskRound`, `Rounds`), the one-deep queue, and the restart route.

**What is true now.** A session killed mid-turn comes back with its draft, its open question and its head sequence,
resumes from any cut with no gap, and the new process can still answer the question. Editing a saved entry writes
one revision of the saved row, moves the edits onto it, and retires the working copy by soft delete, so the library
never grows a second review of the same work. Four rounds of questions is the cap; the fifth is refused with a
typed error rather than a silent nothing.

**Learned.** A revision needs a working copy, because the database will not let a saved row become a draft again
(the trigger says so, and it is right). Copying the row, editing the copy and moving the result back is the shape
that keeps one entry, one revision and no duplicates, and soft-deleting the copy keeps the audit trail of what was
edited.

**Wired by S09.** The queue and the event payloads are the engine's; encoding them into the contract's wire shapes,
and treating a `revises` id as trusted only after checking it names the same work, is the server's job.



## 2026-11-02, S08, the agent pipeline

**Built.** `internal/agent`: the nova embedding, the five tools, the pipeline from a message to a draft card, the
versioned prompts, the budgets and their ledgers, the translation of nova's events into the session's, the
thirty-case invented corpus and its fake-model runner, and `cmd/sepia-eval` for the operator's real-model run.
`SEPIA_OPENROUTER_API_KEY` and `SEPIA_MODEL` (default `deepseek/deepseek-v4.1-flash-1017`, aliases refused) are

**What is true now.** A message becomes a card through the real session engine and real metadata calls. The body is
only ever text the span locator found in her messages; an invented quote is dropped, an invented verdict is left
empty, and `save_entry` refuses a card that fails the save guard. The model cannot set a rating, because the tool

call, a huge argument, a provider outage, a decisions outage, a model error and a model timeout each have a test

**G4, waiting for Autumn.** The corpus and the fake-run report are committed. The odds table from a real run, the
proposed thresholds and the labelling needed are in `docs/handoffs/2026-11-02-G4-corpus-and-odds.md`. No threshold

**Wired by S09.** The socket-backed `agent.Responder`, the wire encoding of the events, the `revises` check against
the same work, and the host and origin guard around the whole turn.


## 2026-11-04, S08 live check

**Run.** The operator supplied temporary OpenRouter and TMDB keys. The pinned chat model
(`deepseek/deepseek-v4.1-flash-1017`) exists and answers; the Jev pre-read is reachable through `/systemone`; TMDB
and OpenLibrary answer. The keys were used in a shell environment only, never written to the repository, a fixture,
a test or a log, and the temporary environment file was deleted after the run. They should be rotated because they
appeared in the chat transcript.

**Result.** A four-case real-title smoke corpus (`internal/agent/testdata/corpus-live.json`) built valid cards for
Dune (book), Dune (film) and The Bear (TV), and exercised the missing-rating `fill_gap` branch on a second Dune
message. The film and TV cases matched their expected fields. The two Dune book cases differed only where the model
chose two exact spans instead of one and chose a verdict: both are her own words and the cards are valid. The

## 2026-11-07, cost keeps whose dollars it was

- **`draft.missing` is a tuple union, not `string[]`.** `.includes('rating')` narrows to `never`; cast once at the

- **The revision target was process memory only.** A restart mid-revision lost it, and confirm saved the working

  failing first.
- **A rejected message lost her text.** The composer had already cleared; the text now goes back into it.
- **A hello could not name an open interaction.** `interaction_id` is in the contract's interaction shape, so a

- **Working was only a live activity row.** While the model streamed there was no row, so Stop vanished and a

- **`reopen` was re-sent on refresh.** It is only sent when the hello carries no card, so refreshing a revision
  does not ask for it twice.
- **Try again re-sent her words as a new message.** A successful retry would have stored and shown them twice.

- **A streaming reply could latch on.** Only nova's `assistant_end` closed a streaming block, and a stop or a

- **`retry` was accepted on a saved session**, where the old Try again is still on screen. It is refused with
